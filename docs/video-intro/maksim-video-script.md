**1. Cold open**

Hey, I'm Maksim — most people call me Max. I've spent the last seven years trying to answer one question: how do you stop bugs before your users find them? Lately that question has a second half too — how do you get AI to help you do that faster, without cutting corners.

**2. Where it started**

It began in 2019, part-time, testing document management software at a small Sydney startup called Aerofiler. My job was basically breaking things on purpose — checking integrations with tools like DocuSign and Salesforce, filing clean bug reports, and slowly realising I actually loved it. 

This is where I learn testing fundamentals, Applied what I learned from Rapid software testing Methodology. I had a lot of freedom to practice exploratory testing . This is where I learned that you can test  with A minimal or no requirement. This is what I liked about the job - you keep exploring, trying to think and act like real users, discovering inconsistencies in business logic, UI or UX. 

**3. The stretch — WithYouWithMe**

**2021 -** From there I moved into a full quality role at WithYouWithMe, testing web applications used across Australia, North America, and the UK. That's where I built the habits that still hold up today — thorough regression testing, clear defect reports, and enough curiosity to learn the API and database layers, not just the UI.

It was my first full time job as a tester at WithYouWithMe. I learned how to work in a testing team, use tools like database, Postman work with developers Deal with multiple environment instances, localization testing,  Regression testing and releases. 
This is where I realised I can actually handle more technical aspects and how powerful they can be. For example the Postman monitoring scripts I created that could give you health signals across 3 production instances (Au, UK, North America) in a few seconds compared to minutes when you check them manually via UI. Or the moments when I finally was able to figure out Playwright locator which is better that the one created originally - more robust, concise and not ugly. 

**4. The build — Figtree Systems**

2023 - One of the important steps for me was at Figtree Systems. I was hired to establish testing framework for both manual testing and automation . There was a lot of challenges related to complex software and custom environments , old technologies and large code base, lack of existing automation in CI/CD, Team of developers, many of whom worked for 15-20 years using the same approach who were sceptical to what I suggested. multiple competing responsibilities which includes QA, manual testing, automation, reporting, coaching. Nevertheless, I'm proud about some of the things I managed to do there. 
For example, Playwright tests covering 50 automated scenarios that ended up saving the team four to six hours of manual work every regression cycle. I also started leading - running workshops on exploratory testing and root cause analysis.

**5. The pivot — Intellihub**

2025 - Then came Intellihub — the number one smart-meter provider in Australia and New Zealand — and a bigger stage: three frameworks, Python and TypeScript, testing systems that handle meter data for over forty electricity retailers. That's where automation stopped being the whole story. 
Yet in Telehub I learned a few things. Number one the speed - From my manager and our automation lead, I learned how fast you can move when you have a handy dashboard the searchable test regression results , A freedom to run and configure Jenkins jobs That can do pretty much anything from monitoring, production and testing environments, running regression tests, sending notifications, handling file uploads, and preparing data automatically for multiple teams, connecting Jira, Zephyr scale and test automation, finding and preparing test data . 

Number two -  Exposure to different frameworks Azure and Smart Core with a playwright TypeScript, the new one, the mature IWS Python Behave framework, And another one with Java tests and Selenium. 


**6. What I actually led **

Somewhere in there I noticed most of my team was curious about AI, but nobody had time to figure it out properly. So I did. I built an AI-powered PR review agent that's saving the team an estimated five to ten percent of review time. I put together five Copilot skills that colleagues use daily. And I started running monthly sessions on practical AI-assisted development — which, honestly, is the part I'm proudest of, because teammates now run their own sessions off the back of it.

And number three, this is where I Started to experiment and apply AI-powered technologies. I started to use extensively things like GitHub copilot skills prompts, sharing them with the team . We did not have access to API from AI provider But that didn't stop us. We got access to Copilot CLI and found a way to   Replace the lack of API access by using CLI We created scheduled Jenkins job.   

So if you ask someone in my IntelliHub team who is Max, they most likely Will call me AI guy Knows about recent trends on GitHub and in AI space , Who is building new agent skills every week And complaining about your user experience and limitations of large enterprise solutions like GitHub Copilot.  

**7. Outside work**

None of this is just a work thing for me. On my own time  I help Scoolendar.com, boostrapped homeschooling platform  where I automate testing using Playwright and Circle CI,  build tools like groundcrew — a bot that turns messy CI failures into plain-language Telegram summaries — and Docfence, a CLI that catches the kind of documentation drift AI assistants quietly introduce. Now it is expanding into helping the platform to explore and utilise ML and AI technology to solve data ingestion, AI-assisted events creation, customer support.


**8. Close — what's next**

So what am I looking for next? Something close to what I've just described, but with more room to run. I do best in smaller, flatter teams, where decisions happen fast and I'm not six layers away from whoever's actually deciding things - not a lot of patience left for bureaucracy for its own sake. I'm based in Sydney, NSW, happy with a hybrid setup, and open to remote work with teams elsewhere too. The roles that fit me best sit across test automation, quality engineering, or the newer space in between — applied AI engineering, AI enablement.

If that sounds like a team you're building, I'd love to talk.
